# 多光源采样实现计划

**状态** · 已完成基线实现与桌面验收，见[实验结果](../experiments/many-light-sampling.md)。

先为 Vulkan 路径追踪器建立可对照的多光源基线。同一个 Cornell 场景分别使用均匀选灯和按发射功率选灯。阅读依据见[多光源采样与 ReSTIR DI 阅读笔记](../reading/many-light-sampling.md)。

## 场景与代码接入

1. **场景数据**。沿用 Cornell 房间、漫反射材质和相机，新建一个桌面可选的多光源测试场景。先用两组布局：一组让几盏灯的功率明显不同，另一组让最亮的灯在部分画面中被挡住。给每盏矩形光源分配稳定索引，同一盏灯的两片三角形共用该索引。
2. **上传光源表**。在 `src/core/scene.*` 把单个 `GpuLight` 改成光源表。随几何生成发光三角形到灯的映射。在 `src/vulkan/renderer.cpp` 沿用当前光源描述符绑定，上传数量和表项，并核对 CPU 与 GLSL 的 `std430` 布局。单灯场景的选灯概率仍为 1，保留原有随机数序列。
3. **选灯与 MIS**。在 `shaders/pathtrace.comp` 先选灯，再在灯面上均匀采样。第一版对少量灯直接查累计概率，按功率的权重用灯面积乘线性发光亮度。显式光源采样和 BSDF 射线命中发光面时，都用**同一盏灯**的选灯概率乘该灯的条件立体角 PDF 来计算 MIS。BSDF 命中时从三角形取灯索引，不能只按材质识别灯，因为不同灯可以共用材质。
4. **运行入口**。通过桌面离屏参数选择多光源场景及选灯策略，复用种子、采样数、线性 PFM 导出和 GPU 计时。第一轮只验收桌面两种基线，ReSTIR DI 的候选重采样和时空复用另立计划。

## 验收方法

| 检查 | 怎么判断 |
| --- | --- |
| 光源数据与概率 | CPU 测试核对每个发光三角形的灯索引、矩形面积和法线、概率归一化。覆盖两盏灯共用同一个发光材质的情况。 |
| 单灯回归 | 现有 Cornell 几何、累积、积分器收敛与能量检查通过。单灯默认入口继续可用。 |
| 多灯正确性 | 先用一次散射隔离直接光照。两种策略分别和独立种子的高样本 BSDF-only 参考图比较。参考图要先验证收敛，避免把参考图的噪声算到候选方法头上。对漫反射区域及遮挡区域分别检查线性亮度误差和平均能量。 |
| 采样效率 | 固定分辨率、采样数和每个着色点的一次选灯机会，用多组种子报告 RMSE 与 GPU 采样耗时。记录实际发出的阴影射线数，因为背向光源的候选可能在发射前就被剔除。若两组射线数不同，按实际射线预算补做对照。 |

按功率选灯的收益由数据决定。亮灯被遮挡时，发射功率和表面实际收到的光照可能差得很远。保留该场景的结果，作为之后判断 ReSTIR DI 是否值得引入的基线。
